## Problem

Most tutorials end with the answer already in hand, so the learner follows and never builds. Open-source projects are the best classroom there is, but a newcomer is faced with a large codebase, an unfamiliar tool (git), and no obvious first step.

## Approach: show the path, not the solution

**Openfirststeps** (the PAN IIT OSS entry for the Hello FOSS programme) is one umbrella repository holding many small teaching repositories, each with a single end goal drawn from everyday life or engineering: reading a flame's soot from video, sizing a heat pump, tuning a spring to a target period, catching a units bug before it flies.

- **Three sessions per repository.** Each session has a short lesson, a notebook, a browser app that runs with nothing to install, exercises, and a checkpoint that says PASS or FAIL, so the learner always knows where they stand.
- **A finished Target to aim for.** Every repository shows the finished animation or playground, and deliberately keeps that code private, so the learner has to build the rest rather than copy it.
- **A path beyond the three sessions.** A roadmap lists what to build next, and open issues are labelled by difficulty (`good first issue`, `beginner`, `intermediate`, `advanced`).
- **Open to first-time contributors.** A contributing guide assumes the reader has never used git.
