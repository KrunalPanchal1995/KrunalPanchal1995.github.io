# Math Studio, static build (portfolio mode)

Generated by `scripts/build_studio_static.py`. Do not edit by hand: re-run the script (it rebuilds this folder from the
Studio source, `STUDY/web/`, which is never modified). Pure static files: GitHub Pages is enough, no Python server.

## What is and is not here
Client-side workspaces run fully: Atlas, Transform 2D/3D, Integrals Lab, Revolve, Surface, Arc, Double, Polar,
Mechanisms, Molecules, Deform & Hair (not preset 19), Solver (ODE tab). A **Reels** workspace plays the shipped
pre-rendered Manim animations and screen recordings (`media/`).
Hidden in static mode (they need the desktop app's Python server or a third-party key): Physics, Intersect, Grapher,
Lessons, Manim (render), Solver equations / PDE / symbolic regression tabs, the recorder button, the help drawer,
the CAD (STEP/STL) export boxes, Deform preset 19 (discrete elastic rods), Desmos 2D/3D, GeoGebra. Visiting such a route
redirects to `#gallery` with the toast "This workspace needs the desktop app". `fetch("api/...")` never reaches the
network: the shim answers it locally.

## Subjects and Explain (WP-C)
`#subjects` (the default workspace: 13 subject cards), `#subjects?s=<id>` (one subject) and `#explain?id=<id>` (one explainer with a
pinned live Studio stage) are client-side routes. Data: `js/studio/explain/data/` (`index.json`, `subjects.json`, `plots.json`, one JSON per
explainer; the 106 plot-class stubs are built in the browser from `plots.json`), plot reference images in `explain/img/plot/`. Generated from
`site/_data/{subjects,figure_explainers,project_images}.yml`, `plot_taxonomy.yml` and the authored explainers by `scripts/explain/`.

## URL options
`index.html?embed=1&portfolio=1&theme=dark#atlas?ch=S32&ex=0`

| option | effect |
|---|---|
| `#<ws>?k=v` | hash route, as in the desktop app (`#atlas?ch=S32&ex=0`, `#deform?preset=2`, `#reels?v=<id>`) |
| `embed=1` | hides the top bar (for iframes); in portfolio mode a small "Gallery" pill appears off the gallery |
| `portfolio=1` | first Gallery section **Projects** (from `projects.json`), a "Projects" link in the top bar, and a bottom bar "Read the project page" while a project's workspace is open |
| `theme=light\|dark` | sets the theme (saved to `localStorage['studio-theme']`, applied through the app's own theme toggle) |
| `api=live` | opt out of static mode (a real backend is present); `api=probe` probes `api/health` and switches itself |

## Messaging protocol (same origin only; the shim checks `event.origin === location.origin`)
parent -> iframe
* `{type:'go', route:'atlas?ch=S32&ex=0'}` sets `location.hash` (a leading `#` is accepted)
* `{type:'theme', theme:'light'|'dark'}`
* `{type:'ping'}` makes the iframe answer `studio-ready` again

iframe -> parent
* `{type:'studio-ready'}` once the window has loaded
* `{type:'studio-route', route}` on every route change (and once at start); `route` has no leading `#`
* `{type:'studio-project', slug, title, route, url:'/projects/<slug>/'}` when a Projects card is clicked
  (`route` is empty when the project has no Studio route; the parent should then open `url`)

## Data files
* `projects.json`: `slug, title, description, img` (site-root relative), `category[]`, `importance`, `route`, `fallback`
  (static fallback route used when `route` is server-only, e.g. pysr-rate-rules), `url`. Built from
  `site/_projects/*.md` front matter; the route comes from the front-matter key `studio:` or `site/_data/studio_map.yml`.
* `media/reels.json`: `id, title, kind (manim|recording), group, video, type, poster, size`.

## Speed build (WP-F2-A)
`scripts/build_studio_static.py` bundles the app with esbuild (code splitting: `js/app-<hash>.js` plus one chunk per workspace in `js/c/`,
minified, content-hashed names, `modulepreload` hints in `index.html`). The Gallery reads `gallery_items.json` (generated from the real
presets at build time) and loads no workspace code; thumbnails load when a card nears the viewport; project and recent cards are 480 px
webp in `thumbs/`. 3D scenes draw only when something changed (see `view3d.js`). Without esbuild/node, or with `--no-bundle`, the build
falls back to the unbundled app (same behaviour, 58 requests).
